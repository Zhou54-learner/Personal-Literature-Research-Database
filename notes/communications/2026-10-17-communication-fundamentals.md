# 通信基础：从信息到信号，再到网络

日期：2026-10-17｜类型：通信原理入门学习整理｜范围：**通信通用基础，不展开无线通信专题**

配套可视化：[通信基础交互概念地图（HTML）](2026-10-17-communication-concept-map.html)。下载后直接用浏览器打开，无需安装依赖。

> **一句话主线：** 通信是在有限且不理想的物理条件下，把发送方的信息表示成可传输的信号，使接收方能够尽可能准确、高效地恢复信息；当多个用户和链路共同工作时，还需要通信网络组织和管理传输。

## 1. 先区分三个基本对象

- **信息（Information）**：希望传递的内容，如文字、语音、图像；不是某一种具体物理波形。
- **信号（Signal）**：承载信息的可测物理量，如电压、光强或电磁场的变化。
- **信道（Channel）**：描述信号从发送端到接收端所经历的传输通路及其特性；不能简单等同于传输媒介。噪声、衰减、失真和干扰会影响接收结果。

因此，要把“**信息是什么**”与“**信息如何表示并通过物理世界传递**”分开考虑。

## 2. 典型数字通信链路

```text
信息源 → [源编码] → 信道编码 → 调制/发送 → 物理信道 → 接收/检测与解调 → 信道译码 → [源解码] → 信息目的地
                                             ↑
                                     噪声、失真、干扰
```

这是理解系统功能的简化图，不是每个系统都必须采用完全相同的模块和顺序。方括号表示源编码/解码可按需要使用；模拟通信也不必先将信息表示成比特。实际数字接收机还常涉及同步、信道估计、均衡等处理。

| 环节 | 主要问题 | 要点 |
| --- | --- | --- |
| **源编码** | 如何更有效地表示信息？ | 减少统计冗余；按用途可无损或有损 |
| **信道编码** | 传输出错后能否恢复？ | 有目的地加入冗余，提高检测或纠错能力 |
| **调制** | 如何将数字信息变为可传输的物理信号？ | 将比特映射为符号，再形成传输波形 |
| **信道** | 信号经历怎样的变化？ | 衰减、噪声、失真、干扰等约束 |
| **接收与译码** | 如何从受扰信号中恢复信息？ | 同步、估计/均衡（视需要）、检测、译码 |

注意：**源编码与信道编码并不矛盾**。前者偏向减少需要发送的信息表示量，后者偏向增加抵抗传输错误的能力。**比特（bit）与调制符号（symbol/码元）也不是同一概念**：一个码元可以映射一个或多个比特，二者速率不能随意等同。

## 3. 从一条链路到整个网络

- **通信链路**：关心两端能否正确传输，包括信号表示、信道、接收及链路性能。
- **通信网络**：有了多用户、多设备和多条链路，还要解决接入、共享资源、寻址、路由、拥塞与服务质量等问题。
- **信息论、信号处理、网络协议**是理解通信的三个互补视角：分别关心传输能力的基本约束、实现传输的具体方法，以及如何组织多用户通信；这不是严格的 OSI 协议分层。

## 4. 性能评价：不能只问“能不能传”

| 关注点 | 典型指标或问题 |
| --- | --- |
| 可靠性 | 误比特率（BER）、误块率（BLER），能否正确恢复 |
| 速率与效率 | 比特率、有效吞吐量、频谱效率（bit/s/Hz） |
| 实时性 | 时延以及随时间变化的稳定性 |
| 资源成本 | 占用带宽、发射功率、能耗、实现复杂度 |

**存在权衡**：更可靠的传输可能需要更多冗余或资源；提高传输速率不一定提高有效吞吐量。比较方案时必须说明约束和评价指标。

## 5. 读下一篇综述时的定位问题

面对任何一项通信技术，先问：**它传递什么信息？如何表示成信号？主要信道限制是什么？发送和接收端分别承担什么工作？改进了哪项性能、代价是什么？它处理的是单条链路还是整个网络？**

这六个问题足以作为后续阅读 AI＋通信综述的基本定位工具。**无线信道、OFDM、MIMO、波束形成、CSI 等具体专题另行展开**，不在本笔记里预先扩展。
